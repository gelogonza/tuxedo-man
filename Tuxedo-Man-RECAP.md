# The Tuxedo Man
An interactive horror project that combines a browser-based game with physical Arduino controls and feedback. The goal was to make the player’s physical actions part of the suspense. The game places the player in a dark forest with a mysterious figure following them, using sound, lighting, character animation, and limited visibility to create tension. We later extended the project into a coffin-shaped enclosure that brings the hardware into the same horror theme as the game.
---------
The digital experience combines a three.js environment, an animated character, synthesized audio, and visual effects. An Arduino communicates with the browser through USB serial, allowing physical inputs to affect the game. Covering the photoresistor closes the player’s eyes, moving a hand toward the distance sensor controls a reaching interaction, and different button presses trigger actions such as looking behind, controlling the flashlight, and crouching. The NeoPixel changes color and the servo provides movement, giving events on screen a physical presence.
-----------
One successful aspect was how the sensors worked together to support the experience. Although the distance-sensing system included a primary laser sensor and a Sharp fallback, the inputs contributed to a shared interaction rather than functioning only as isolated controls. The photoresistor added another layer by letting the player affect visibility while interacting with the other inputs. This made physical participation central to the game. Getting reliable readings required adjustments, including using analog readings and a startup baseline for the Sharp sensor because its output was too low for reliable digital detection.
-----------
The physical enclosure introduced different challenges. We attempted to create the coffin through 3D modeling and laser cutting, but could not get the dimensions and measurements correct. We eventually switched to cardboard, which allowed us to continue assembling the prototype and adjust component placement directly. We installed the electronics inside, added a wired button that could reach outside the casket, and made openings for the button and distance sensor.
---------
We also reconsidered the original mechanical concept. The plan included knocking and an opening lid, but we removed the knocking because it added complexity without enough benefit in that version. Looking back, we could have measured the components more carefully and tested a full-scale enclosure mockup before attempting fabrication. Earlier testing would have helped us account for wiring, mounting, sensor access, and the space required by moving parts.
---------
If we continue the game, we would keep the core controls and develop more story and interactive storytelling. The physical actions already provide a foundation; the next step would be giving them more narrative meaning. For the enclosure, we would simplify the design into a closed coffin with dedicated sensor slots on top, a visible opening for the NeoPixel, and an opening with more clearance around the photoresistor. We could also reconsider the servo as a knocking effect tied directly to the character’s proximity in the game. In that role, knocking would communicate danger through the physical object and strengthen the connection between the coffin and what happens on screen.
